## OOP Fundamentals

### Classes, Objects, Properties, and Methods

#### Object Allocation & References

- In PHP, objects are passed by handle (often referred to as passing by reference)
- Though technically it is passing a copy of an object identifier value.

```php
$user1 = new User("Alice");
$user2 = $user1;          // Both point to the same object instance
$user2->name = "Bob";     // Modifies $user1->name as well!

$user3 = clone $user1;    // Creates a shallow copy of the object
```

#### Constructors & Property Promotion (PHP 8.0+)

- Legacy PHP uses explicit property declarations and manual assignment inside `__construct()`.
- Modern PHP codebases use Constructor Property Promotion, which combines parameter declaration and property assignment into one step.

```php
// Modern Syntax (PHP 8.0+)
class User {
    public function __construct(
        public int $id,
        public string $name,
        private ?string $email = null
    ) {}
}

// Legacy Equivalent
class User {
    public int $id;
    public string $name;
    private ?string $email;

    public function __construct(int $id, string $name, ?string $email = null) {
        $this->id = $id;
        $this->name = $name;
        $this->email = $email;
    }
}
```

#### Critical PHP Traps & Gotchas
- The `$this` Keyword
    - Unbound variables inside a method do not resolve to class properties.
    - `$this->propertyName` must be used explicitly to access an instance property.
    - Missing `$this->` will look for a local variable instead.
- Uninitialized Typed Properties
    - If a property has a type hint (e.g., `public string $name;`) and is accessed before assignment, PHP throws an `Error: Typed property User::$name must not be accessed before initialization`.
    - Use `isset($this->name)` to check initialization state safely.
- Dynamic Properties (Deprecated in PHP 8.2+)
    - Historically, setting an undeclared property (`$user->unknownProp = 10;`) created a dynamic property on the fly.
    - In PHP 8.2+, this emits a deprecation warning unless the class uses the `#[AllowDynamicProperties]` attribute or implements `__set()`.

### Visibility Modifiers
PHP enforces `public`, `protected`, and `private` at runtime.

| Modifier    | Access from Current Class | Access from Child Classes | Access from Outside Instance |
|-------------|---------------------------|---------------------------|------------------------------|
| `public`    | Yes                       | Yes                       | Yes                          |
| `protected` | Yes                       | Yes                       | No                           |
| `private`   | Yes                       | No                        | No                           |

#### PHP-Specific Access Behaviors
- Default Visibility
    - If no modifier is specified on a method or property, PHP defaults it to `public`.
    - Best practice is explicit visibility.
- Accessing Private Members Across Same-Class Instances
    - An instance of a class can access private properties of other instances of the exact same class.
    - This is frequently used in custom ORMs for cloning or merging model states.
- Readonly Properties (PHP 8.1+)
    - Properties can be marked `readonly`.
    - They can only be initialized once (usually in the constructor) and cannot be modified afterward regardless of visibility.

### Static methods/properties
| Scope Keyword   | Meaning in PHP                                               | Syntax Example          |
|-----------------|--------------------------------------------------------------|-------------------------|
| `$this->`       | References the current object instance                       | `$this->name`           |
| `self::`        | References the class where the code is written               | `self::$count`          |
| `static::`      | References the called class at runtime (Late Static Binding) | `static::find()`        |
| `parent::`      | References the parent class                                  | `parent::__construct()` |

#### Late Static Binding (`self::` vs `static::`)
- When a parent base class (like `Model`) provides static query methods (like `User::find()`), using `self::` points to `Model`, whereas `static::` points to `User`.

```php
abstract class BaseModel {
    public static function getTableNameSelf(): string {
        return self::$table; // Binds at compile-time to BaseModel
    }

    public static function getTableNameStatic(): string {
        return static::$table; // Binds at runtime to the calling child class
    }
}

class User extends BaseModel {
    protected static string $table = 'users';
}

// User::getTableNameSelf();   --> Error: Undefined static property BaseModel::$table
// User::getTableNameStatic(); --> Returns "users"
```

#### Static Traps to Watch For
- Calling `$this` inside a static method throws an immediate `Error: Using $this when not in object context`.
- Static properties are shared globally across all instances and requests within that worker process scope. They do not reset automatically between methods unless explicitly re-assigned.

### Interfaces
- Contain only public method signatures (and constant definitions).
- Classes implement interfaces using `implements InterfaceA, InterfaceB`.
- As of PHP 8.0, interfaces can define method parameters with type hints, union types, and return types that implementing classes must strictly match or widen.

### Abstract Classes
- Cannot be instantiated directly using `new`.
- Can contain concrete methods with body logic, static methods, and properties alongside `abstract` method definitions.
- Child classes extend abstract classes using `extends ParentClass`.
- PHP supports single class inheritance only.

### Traits (Horizontal Code Reuse)
- Traits allow developers to inject reusable methods and properties into unrelated classes without using inheritance.
- They are heavily used in custom ORMs for adding features like soft-deletes, timestamp tracking, or logging.

```php
trait SoftDelete {
    protected ?string $deletedAt = null;

    public function delete(): void {
        $this->deletedAt = date('Y-m-d H:i:s');
        $this->save();
    }
}

class User extends BaseModel {
    use SoftDelete; // Injects $deletedAt property and delete() method into User
}

class Post extends BaseModel {
    use SoftDelete; // Reuses exact same logic in Post
}
```

#### Gotchas with Traits
- Precedence Rules
    - Methods declared on the current class override Trait methods.
    - Trait methods override inherited methods from a parent class.
    - Precedence Order: `Current Class Method > Trait Method > Extended Parent Method`.
- Naming Collisions
    - If two traits imported by the same class define a method with the exact same name, PHP throws a fatal compile error unless resolved using the `insteadof` operator:
        ```php
        class Product {
            use TraitA, TraitB {
                TraitA::log insteadof TraitB; // Explicitly pick TraitA's log method
            }
        }
        ```

## Magic Methods
- These are reserved methods prefixed with two underscores (`__`).
- They act as event hooks triggered automatically by the runtime in response to specific actions—such as accessing non-existent properties, calling missing methods, or serializing an object.

### Object Lifecycle

#### __construct()
- Executes automatically when an object is instantiated via `new`.
- Used for dependency injection, initializing model attributes, or opening database/file connections.

#### __destruct()
- Executes automatically when no references to the object remain in memory, or during script shutdown.
- Used for cleanups, closing database connections, flushing log buffers, or removing temporary locks.
- It runs when memory is cleared by PHP's garbage collector.
- If a script calls `exit()` or throws an uncaught exception, destructors still run during the shutdown phase, but their output buffers might already be closed.

### Property Interception
- In standard Active Record ORMs, database columns (e.g., `email`, `created_at`) are not hardcoded as explicit class properties.
- Instead, they are stored internally in a key-value `$attributes` array.
- When code accesses `$user->email`, PHP notices that `$email` is not declared on the class and automatically delegates the action to `__get()` and `__set()`.

```php
$user = new User();
$user->name = "Alice"; // Fires __set('name', 'Alice') -> populates $attributes['name']
echo $user->name;      // Fires __get('name')         -> returns $attributes['name']
```

### Dynamic Method Interception
- These methods allow classes to handle dynamic method invocations at runtime without defining dozens of concrete functions.
- `__call(string $name, array $arguments)` is triggered when calling an inaccessible or non-existent instance method.
- `__callStatic(string $name, array $arguments)` is triggered when calling an inaccessible or non-existent static method.

```php
class User extends Model {
    public static function __callStatic(string $method, array $args): mixed {
        if (str_starts_with($method, 'findBy')) {
            $column = strtolower(substr($method, 6));
            $value  = $args[0] ?? null;
            return (new static())->where($column, '=', $value)->first();
        }
        throw new BadMethodCallException("Method {$method} does not exist.");
    }

    public function __call(string $method, array $args): mixed {
        return $this->newQueryBuilder()->$method(...$args);
    }
}

// Tracing execution:
$user = User::findByName("Alice"); 
// 1. PHP checks if User::findByName() exists. It doesn't.
// 2. PHP calls User::__callStatic('findByName', ['Alice']).
// 3. Method parses 'findByName' -> column 'name', executes SQL query automatically.
```

### Serialization and Type Casting
- When sending model instances over a REST API response, PHP needs to convert rich objects into formatted JSON payloads or string structures.
- `__toString()` defines how an object behaves when cast to a string (e.g., `echo $user;` or `(string)$user`).
    - Must return a string and cannot throw uncaught exceptions in older PHP versions.
- `jsonSerialize()` (`JsonSerializable` Interface)
    - While not an underscore magic method itself, `JsonSerializable` works hand-in-hand with `json_encode()`.
    - When an object is passed into `json_encode($user)`, PHP checks if it implements `JsonSerializable`.
    - If so, it invokes `jsonSerialize()` to extract serializable data.

## Namespaces & Autoloading
- Modern and legacy raw PHP systems use Namespaces to prevent class name collisions and Autoloaders to automatically locate and load file paths into memory on demand, instead of hundreds of manual `require_once` or `include_once` statements at the top of files.

### Namespace definitions and `use` imports
- Namespaces resolve class name conflicts by organizing code into logical directories/virtual modules, similar to packages in Java or namespaces in C#.
- A namespace definition must be the very first statement in a PHP file (except for `declare()` statements).
- Inside a declared namespace, PHP assumes any un-imported class belongs to the current namespace.
    - To call native PHP classes (like `PDO`, `Exception`, `DateTime`) or global legacy functions from inside a namespace, they must be prefixed with a leading backslash `\` or imported with `use`.
- When referencing a class defined in another namespace, it is imported using the `use` keyword.
- PHP allows importing functions and constants directly using `use function` and `use const`.

```php
<?php
namespace App\Models;

class User {
    // Fully Qualified Name (FQN): \App\Models\User
    // ERROR: PHP looks for \App\Models\PDO!
    $pdo = new PDO(...);

    // CORRECT: Leading \ instructs PHP to look in the Global Namespace
    $pdo = new \PDO(...);
}
```

```php
<?php
namespace App\Controllers;

use App\Models\User;                    // Imports \App\Models\User
use App\Services\Auth\JWT as Tokenizer; // Class Aliasing
use function App\Helpers\format_date;
use const App\Config\MAX_RETRIES;

class AuthController {
    public function login(): void {
        $user = new User();              // Refers to \App\Models\User
        $token = Tokenizer::generate();  // Refers to \App\Services\Auth\JWT
    }
}
```

### Autoloading Mechanics
- It is the engine mechanism that eliminates manual `require` statements.
- When PHP encounters a class that hasn't been defined yet (e.g., `new User()`), it triggers an autoload hook before throwing a "Class not found" error.
- `spl_autoload_register()` is a native PHP function that registers custom callback functions to run whenever an unmapped class name is referenced.

```php
<?php
spl_autoload_register(function (string $className) {
    // Convert namespace separators (\) to system directory separators (/)
    // App\Models\User -> App/Models/User
    $path = str_replace('\\', '/', $className);

    // Build full file path on disk
    $file = __DIR__ . '/src/' . $path . '.php';

    // Include the file if it exists
    if (file_exists($file)) {
        require_once $file;
    }
});

// When execution reaches this line:
$user = new \App\Models\User(); 
// PHP automatically passes 'App\Models\User' to the callback above!
```

#### The PSR-4 Autoloading Standard
- PSR-4 (PHP Standard Recommendation 4) is the industry standard specification for mapping namespace prefixes to physical file directory paths.
- The standard for autoloading is that an absolute class name takes the following form: $$\text{\textbackslash NamespacePrefix\textbackslash SubNamespaces\textbackslash ClassName}$$
- A contiguous namespace prefix maps to a base directory on disk.
- The sub-namespaces directly map to sub-directories underneath that base directory.
- The class name maps strictly to `ClassName.php` (case-sensitive).

#### Autoload Mapping
- Composer is frequently used solely as an autoloader and dependency manager.
- It reads configuration settings inside `composer.json` to generate an optimized, high-performance autoloader script.
- For Composer's autoloader to function, the main entry point file (`index.php` or `bootstrap.php`) requires a single file.

```json
{
    "autoload": {
        "psr-4": {
            "App\\": "src/",
            "Database\\": "database/"
        },
        "files": [
            "src/Helpers/global_functions.php"
        ]
    }
}
```

```php
<?php
// index.php

require_once __DIR__ . '/vendor/autoload.php';

// Everything below this line is automatically loaded on demand!
$router = new \App\Core\Router();
$router->dispatch();
```
