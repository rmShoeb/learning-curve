## PHP Data Objects Core
- PDO is the standard native database abstraction layer in modern PHP applications.
- It provides a uniform interface for database interaction, enforces prepared statements, and isolates lower-level driver mechanics.

### Establishing PDO connections
- A PDO instance is created by passing a Data Source Name (DSN), database username, password, and driver configuration options to its constructor.
- **Data Source Name (DSN)** format consists of the driver prefix (e.g., `mysql:`), followed by database host, name, port, and character encoding parameters separated by semicolons.
- **Character Set Specification:** Setting `charset=utf8mb4` inside the DSN guarantees UTF-8 handling at the connection level, preventing Unicode conversion exploits.
- **Connection Error Leakage:** Instantiating PDO directly inside `try`-`catch` blocks is required to prevent raw stack traces from exposing database credentials in unhandled exception output.
- Native Emulation (`PDO::ATTR_EMULATE_PREPARES`)
    - When `true` (default in older PHP versions), PDO emulates prepared statements natively in PHP before sending raw SQL strings to MySQL.
    - When `false`, PDO sends actual prepared statements to MySQL via the binary protocol, forcing the database engine to parse and compile the SQL template independently of runtime parameters.

```php
<?php
$dsn = 'mysql:host=rds-primary.c123456.us-east-1.rds.amazonaws.com;dbname=app_db;port=3306;charset=utf8mb4';
$username = 'db_user';
$password = 'secret_pass';

$options = [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    PDO::ATTR_EMULATE_PREPARES   => false,
];

try {
    $pdo = new PDO($dsn, $username, $password, $options);
} catch (PDOException $e) {
    // Exception message contains sensitive host/credential information
}
>
```

### Prepared statements and Parameter binding
- Prepared statements separate SQL compilation from execution, rendering parameter payload values incapable of altering SQL query structure.
- Positional Placeholders (`?`)
    ```php
    <?php
    $sql = "SELECT id, email, status FROM users WHERE status = ? AND created_at >= ?";
    $stmt = $pdo->prepare($sql);

    $stmt->execute(['active', '2026-01-01 00:00:00']);
    $users = $stmt->fetchAll();
    >
    ```
- Named Placeholders (`:name`)
    - `bindValue()` passes the value directly at the moment of binding.
    - `bindParam()` binds by reference (`&$variable`), evaluating the value only when `$stmt->execute()` is invoked.
    - Using `bindParam()` inside loops without careful variable management can introduce unexpected state mutation bugs.
    ```php
    <?php
    $sql = "SELECT id, email, status FROM users WHERE status = :status AND created_at >= :created_at";
    $stmt = $pdo->prepare($sql);

    // Explicit binding with data types
    $stmt->bindValue(':status', 'active', PDO::PARAM_STR);
    $stmt->bindValue(':created_at', '2026-01-01 00:00:00', PDO::PARAM_STR);
    $stmt->execute();
    >
    ```

### Fetch modes
- Fetch modes determine how query result rows are structured in memory.
- `PDO::FETCH_ASSOC` returns an array indexed by column name.
- `PDO::FETCH_OBJ` returns an anonymous `stdClass` object with property names matching SQL result set columns.
- `PDO::FETCH_CLASS` instantiates instances of a specified class, mapping columns directly to class properties before calling the class constructor.
- `FETCH_CLASS` Property Assignment Ordering:
    - PDO hydrates properties before invoking `__construct()`.
    - If class property defaults are declared in code, constructor assignments will overwrite values hydrated by PDO during execution.

```php
<?php
class UserEntity {
    public int $id;
    public string $username;
    public string $email;
}


$stmt = $pdo->prepare("SELECT id, username, email FROM users WHERE id = :id");
$stmt->execute([':id' => 42]);

$row = $stmt->fetch(PDO::FETCH_ASSOC);
// Output: ['id' => 42, 'username' => 'alex', 'email' => 'alex@example.com']

$row = $stmt->fetch(PDO::FETCH_OBJ);
// Output: $row->id (42), $row->username ('alex')


$stmt->setFetchMode(PDO::FETCH_CLASS, UserEntity::class);
$user = $stmt->fetch(); // $user is an instance of UserEntity
>
```

### Error Handling Modes (`PDO::ATTR_ERRMODE`)
- `PDO::ERRMODE_SILENT` (Legacy Default): Sets error codes silently. Requires manual checking of `$pdo->errorCode()` or `$stmt->errorInfo()`.
- `PDO::ERRMODE_WARNING`: Emits a PHP runtime `E_WARNING` while continuing script execution.
- `PDO::ERRMODE_EXCEPTION` (Modern Standard): Throws a `PDOException` on any database failure, allowing block transaction management.

### Transaction Control
- DDL commands trigger implicit transaction commits in MySQL.
- Enclosing DDL queries inside PDO transactions will break rollback functionality.

```php
<?php
// sample transaction handling
try {
    $pdo->beginTransaction();

    $stmt1 = $pdo->prepare("UPDATE accounts SET balance = balance - :amount WHERE id = :from");
    $stmt1->execute([':amount' => 100, ':from' => 1]);

    $stmt2 = $pdo->prepare("UPDATE accounts SET balance = balance + :amount WHERE id = :to");
    $stmt2->execute([':amount' => 100, ':to' => 2]);

    $pdo->commit();
} catch (PDOException $e) {
    if ($pdo->inTransaction()) {
        $pdo->rollBack();
    }
    throw $e;
}
>
```

## Deconstructing the Active Record Pattern
- The Active Record architectural pattern maps a database table or view to a class, and an individual database row to an instance of that class.
- **Single Responsibility Dual Role:** An Active Record instance carries both business domain data (row attributes) and database persistence behavior (`save()`, `delete()`, `update()`).

    ```
    Database Table: `users`               PHP Class Definition: `User`
    +----+----------+-----------------+   +--------------------------------+
    | id | name     | email           |   | class User extends Model { ... }|
    +----+----------+-----------------+   +--------------------------------+
    |  1 | Alice    | alice@test.com  |  ---> $user1 = new User(); (Row 1)
    |  2 | Bob      | bob@test.com    |  ---> $user2 = new User(); (Row 2)
    +----+----------+-----------------+
    ```

- Rather than declaring static public class properties for every database table column, custom Active Record implementations intercept reads and writes using internal key-value storage.

    ```php
    <?php
    abstract class ActiveRecord {
        protected array $attributes = [];
        protected array $original = [];

        public function __construct(array $attributes = []) {
            $this->fill($attributes);
        }

        public function fill(array $attributes): void {
            foreach ($attributes as $key => $value) {
                $this->__set($key, $value);
            }
        }

        public function __get(string $key): mixed {
            // Support custom getter mutators (e.g., getFirstNameAttribute)
            $mutator = 'get' . $this->studly($key) . 'Attribute';
            if (method_exists($this, $mutator)) {
                return $this->$mutator();
            }

            return $this->attributes[$key] ?? null;
        }

        public function __set(string $key, mixed $value): void {
            // Support custom setter mutators (e.g., setPasswordAttribute)
            $mutator = 'set' . $this->studly($key) . 'Attribute';
            if (method_exists($this, $mutator)) {
                $this->$mutator($value);
                return;
            }

            $this->attributes[$key] = $value;
        }

        protected function studly(string $value): string {
            return str_replace(' ', '', ucwords(str_replace(['-', '_'], ' ', $value)));
        }
    }
    >
    ```

- To avoid generating unnecessary update queries that overwrite unchanged columns, active record models maintain an internal record of original attributes populated during database hydration.


## Dissecting Custom Database Wrappers
- Custom frameworks implement proprietary abstraction wrappers around PDO to provide fluid query building, model hydration, relation handling, and connection management.
- Query Builders accumulate SQL fragments inside private array properties and assemble a complete, parameter-bound SQL string upon calling terminal methods like `get()` or `first()`.
- Custom Active Record implementations resolve associations either through dynamic methods that execute secondary queries, or by auto-generating join clauses.
- Invoking relationship methods inside loops (e.g., looping through 100 posts and executing `$post->author()` on each iteration) executes $N+1$ discrete database queries.
- Code bases address this via manual eager loading implementations (`WHERE IN (...)`).
- Production setups with AWS RDS utilize an Amazon RDS Writer Endpoint (Primary DB) alongside one or more Reader Endpoints (Read Replicas).
- Custom database abstraction layers manage connection splitting to route traffic efficiently and offload read execution.
