## Data Types & Type Juggling
This section focuses on how PHP interprets data under the hood, how legacy implicit type conversions cause hidden bugs, and how modern PHP type signatures clarify code intent.

### Built-in Types
PHP has eight primary primitive/built-in types divided into standard categories.

#### Scalar Types (Single-value containers)
- `bool`
    - `true` or `false`
    - case-insensitive in raw PHP: `TRUE`, `False`.
- `int`
    - Whole numbers (e.g., 42, -10).
    - On 64-bit systems, `PHP_INT_MAX` is $2^{63}-1$.
- `float`
    - Also historically called `double`
    - Floating-point numbers (e.g., 3.14, 1.0).
- `string`
    - Series of characters.
    - Strings can be enclosed in single quotes (`'...'`) or double quotes (`"..."`).
    - Double-quoted strings support variable interpolation.

    ```php
    <?php
    $id = 45;
    $sql = "SELECT * FROM users WHERE id = $id"; // Variable $id expands to 45
    $sql = 'SELECT * FROM users WHERE id = $id'; // Literal string, no expansion
    >
    ```

#### Compound Types
- `array`
    - In PHP, an array is actually an ordered map, it maps keys to values.
    - It acts as a list, hash map, dictionary, stack, and queue all at once.

    ```php
    <?php
    // Modern short array syntax (PHP 5.4+)
    $user = ['id' => 1, 'name' => 'Alice'];
    
    // Legacy array syntax (Very common in older code bases)
    $user = array('id' => 1, 'name' => 'Alice');
    >
    ```

- `object`
    - Instance of a class.
- `callable`
    - A reference to something that can be invoked as a function.
    - Strings naming a function, or arrays like `[$instance, 'methodName']`.

#### Special Types
- `null`
    - Represents a variable with no value.
    - A variable is `null` if it has been assigned the constant `NULL`, has not been initialized yet, or was `unset()`.
- `resource`
    - Holds a reference to an external resource (e.g., an open database connection, a file handle returned by `fopen()`).

### Strict and Weak Typing, Type Juggling
- PHP is traditionally a dynamically and weakly typed language.
- It does not require to declare variable types explicitly when creating variables (e.g., `$x = 10;`).
- Type Juggling is PHP's automatic conversion of data types depending on the context in which an expression is evaluated.
- By default, PHP operates in Weak Typing Mode.
- If a function expects an `int` and calling method passes the string `"123"`, PHP coerces it to `123` silently.
- Modern PHP (7.0+) allows developers to enforce Strict Typing Mode on a per-file basis using a directive at the top of the file.
    - This only affects function calls made from within that specific file.
    - If File A (without strict types) calls a function declared in File B (which has strict types), the call is evaluated in weak mode (File A's setting governs the call site).
    - It strictly checks `int`, `float`, `string`, and `bool`.

```php
<?php
declare(strict_types=1);

function setAge(int $age) {
    return "Age set to " . $age;
}

setAge(30);     // Works fine
setAge("30");   // Throws a TypeError when strict_types=1 is active
>
```

#### Common Automatic Conversions
- **String to Numeric Expressions:** If an operator expects a number (like `+`), PHP converts strings to numbers.
```php
<?php
$total = "10" + 20;     // Result: (int) 30
$total = "10.5" + 20;   // Result: (float) 30.5

// PHP 7.x Legacy Behavior (PHP 8 throws a TypeError or Warning):
$total = "10 apples" + 5; // Result: (int) 15 (Extracts leading numeric part)
>
```
- **Truthy and Falsy Evaluations:**
    - In conditional checks (`if ($var)`), PHP casts values to boolean automatically.
- **Loose Comparison vs. Strict Comparison**
    - `==` (Equal): Checks value after type juggling.
    - `===` (Identical): Checks value and type without conversion.

### Type hinting

#### Basic Parameter and Return Type Declarations (PHP 7.0+)
- Function signatures can explicitly declare input parameters and return types.
```php
<?php
function calculateTax(float $amount, float $rate): float {
    return $amount * $rate;
}
>
```

#### Nullable Types (`?Type`) (PHP 7.1+)
- By default, typed parameters/returns do not accept `null`.
- Prefixing a type with `?` makes it explicit that `null` is a valid value.
```php
<?php
// $user can be an instance of User OR null
// Returns a string OR null
function getUsername(?User $user): ?string {
    if ($user === null) {
        return null;
    }
    return $user->name;
}
>
```

#### Union Types (`TypeA|TypeB`) (PHP 8.0+)
- Allows a variable, parameter, or return value to accept multiple distinct types.
```php
<?php
class UserRepository {
    // $id can be an integer (12) or string UUID ("a1b2-c3d4")
    public function findUser(int|string $id): User|false {
        // Query database...
        if (!$found) {
            return false; // Very common legacy pattern: return false on failure
        }
        return $user;
    }
}
>
```

#### Specialized Types
- `mixed`: Equivalent to `array|bool|callable|int|float|object|resource|string|null`. Means "any value."
- `void`: Indicates a function performs an action but returns no value (using `return;` or returning nothing).
- `never`: Indicates a function never terminates normally (it either calls `exit()`, `die()`, or throws an Exception).

## Native PHP Arrays

### Indexed vs. Associative arrays
Unlike languages with distinct `List`, `Map`, or `Dictionary` types, PHP uses a single `array` type that acts as an ordered hash map.

#### Indexed Arrays
- Keys are automatically assigned integers starting at `0` unless specified otherwise.
- Deleting an item with `unset($array[1])` does not re-index the remaining items. The array becomes `[0 => 'a', 2 => 'c']`.

```php
<?php
$statuses = ['active', 'pending', 'inactive'];

// Behind the scenes, PHP stores this as:
// [0 => 'active', 1 => 'pending', 2 => 'inactive']
>
```

#### Associative Arrays
- Keys are custom strings or custom integers.
- This is how raw database rows and JSON payloads are represented when converted to PHP.
- PHP allows mixing integer and string keys in the same array.
- PHP automatically converts numeric string keys to integers.

```php
<?php
$user = [
    'id' => 42,
    'email' => 'alex@example.com',
    'role' => 'admin',
    '10' => 'A', // Key '10' is silently cast to integer 10
    10   => 'B'  // Overwrites the key 10! Value is now 'B'
];
>
```

### Array Destruction and Spreading
- Destructuring is extracting array elements directly into variables.
- `list()` is the old syntax and `[]` is the modern syntax.

```php
<?php
// Modern Short Syntax (PHP 7.1+)
[$id, $name] = [101, 'Data Reader'];

// Legacy Equivalent (Very common in older code)
list($id, $name) = array(101, 'Data Reader');

// Keyed Destructuring (Extract specific keys from associative arrays)
['email' => $userEmail, 'role' => $userRole] = $user;
// $userEmail is now 'alex@example.com'
>
```

- Array unpacking / spread operator (`...`) is used to expand an array inline or pass positional parameters into functions.

```php
<?php
// 1. Merging Arrays (PHP 7.4+ for indexed, PHP 8.1+ for associative)
$baseRoles = ['user', 'editor'];
$allRoles  = [...$baseRoles, 'admin', 'superadmin'];
// Result: ['user', 'editor', 'admin', 'superadmin']

// 2. Variadic Functions (Unpacking parameters)
function executeQuery(string $sql, ...$params) {
    // $params inside the function is an array containing all extra arguments passed
}

$args = [42, 'active'];
executeQuery("SELECT * FROM users WHERE id = ? AND status = ?", ...$args);
// Expands to: executeQuery("...", 42, 'active')
>
```

### Essential Array Functions

- `array_map()`: Applies a callback function to every element and returns a new array of the exact same length.
    ```php
    <?php
    $rawUserIds = ['1', '2', '3'];
    
    // Convert array of string IDs to integers (Common during API query parsing)
    $cleanIds = array_map(function($id) {
        return (int) $id;
    }, $rawUserIds);
    // Result: [1, 2, 3]
    >
    ```
- `array_filter()`: Iterates over elements and keeps only those where the callback returns `true`.
    ```php
    <?php
    $rows = [
        ['id' => 1, 'deleted' => false],
        ['id' => 2, 'deleted' => true],
        ['id' => 3, 'deleted' => false]
    ];

    // Strip out soft-deleted records
    $activeRows = array_filter($rows, function($row) {
        return !$row['deleted'];
    });
    // this cannot make filtering decisions based on the keys
    // PRESERVES original keys ([0 => row1, 2 => row3]).
    // array_values() reset keys back to sequential [0, 1].
    >
    ```

    - `ARRAY_FILTER_USE_KEY` modifies the behavior so that PHP passes only the array key into the callback function instead of the value.
        ```php
        <?php
        $payload = [
            'username' => 'john_doe',
            'email'    => 'john@example.com',
            'is_admin' => 1 // <--- Malicious attempts to escalate privilege
        ];
        $allowedColumns = ['username', 'email']; // Database columns allowed to be updated by this API endpoint

        // Filter the payload by checking its KEYS against allowed columns
        $safePayload = array_filter(
            $payload, 
            function($key) use ($allowedColumns) {
                // $key receives: 'username', 'email', 'is_admin'
                return in_array($key, $allowedColumns, true);
            }, 
            ARRAY_FILTER_USE_KEY // <--- Flag telling array_filter to pass keys to the callback
        );

        // Result of $safePayload:
        // ['username' => 'john_doe', 'email' => 'john@example.com']
        >
        ```

    - `ARRAY_FILTER_USE_BOTH` flag passes both the value and the key into the callback as two distinct arguments.
        ```php
        <?php
        $data = [
            'first_name' => 'John',
            'last_name'  => '',
            'role'       => 'admin'
        ];

        $result = array_filter(
            $data, 
            function($val, $key) {
                // Note the order: ($value, $key)
                // Keep only if the key doesn't start with 'last_' AND value is not empty
                return strpos($key, 'last_') !== 0 && $val !== '';
            }, 
            ARRAY_FILTER_USE_BOTH
        );
        >
        ```
- `array_reduce`: Iterates through an array to reduce it down to a single output (e.g., building a SQL string or calculating a total).
    ```php
    <?php
    $conditions = ['status = "active"', 'age > 18', 'role = "admin"'];

    // Build a raw SQL WHERE clause
    $whereClause = array_reduce($conditions, function($carry, $item) {
        return $carry === '' ? $item : $carry . ' AND ' . $item;
    }, '');
    // Result: 'status = "active" AND age > 18 AND role = "admin"'
    >
    ```
- `array_merge()`: Combines one or more arrays.
    ```php
    <?php
    $defaults = ['status' => 'pending', 'limit' => 10];
    $input    = ['limit' => 25, 'page' => 2];
    
    $config = array_merge($defaults, $input);
    // Result: ['status' => 'pending', 'limit' => 25, 'page' => 2]
    // Rule: String keys in later arrays OVERWRITE earlier ones.
    >
    ```
- `in_array()`: Checks if a value exists inside an array.
    ```php
    <?php
    if (in_array($requestedRole, ['admin', 'manager'])) {
        // Grant elevated access
    }
    
    // CRITICAL SAFETY WARNING: Loose vs Strict
    in_array(0, ['admin', 'manager']);       // returns true in PHP 7.x due to loose comparison!
    in_array(0, ['admin', 'manager'], true); // Third parameter enforcing strict check (===) returns false
    >
    ```

## Control Structures
Conditional execution structures dictate how request routing, feature flags, permissions, and database queries branching occur.

### Standard `if` / `elseif` / `else`

```php
<?php
if ($user['role'] === 'admin') {
    $canAccess = true;
} elseif ($user['role'] === 'editor' && $isOwner) {
    $canAccess = true;
} else {
    $canAccess = false;
}
>
```

### Alternative Syntax (`if ... : ... endif;`)

```php
<?php if ($user['status'] === 'active'): ?>
    <span class="badge active">Active User</span>
<?php elseif ($user['status'] === 'pending'): ?>
    <span class="badge pending">Pending Approval</span>
<?php else: ?>
    <span class="badge inactive">Disabled</span>
<?php endif; ?>
```

### Short Hand Conditionals

```php
<?php
// Standard Ternary Operator
$page = isset($_GET['page']) ? (int)$_GET['page'] : 1;

// Shorthand Ternary
// If $_POST['title'] is empty string or unset, fallback to 'Untitled'
$title = $_POST['title'] ?: 'Untitled';

// Null Coalescing Operator (PHP 7.0+)
$limit = $_GET['limit'] ?? 20;
// Chaining null coalescing (reads left to right until first non-null)
$tenantId = $_GET['tenant_id'] ?? $_SESSION['tenant_id'] ?? 'default';

// Null Coalescing Assignment Operator (PHP 7.4+)
// Assigns the right side to the left variable only if the left variable is null or unassigned.
$config['db_port'] ??= 3306;
>
```

### `switch` Statement
- It is widely used in raw PHP REST API routers to execute different code depending on `$_SERVER['REQUEST_METHOD']` or API action parameters.
- A common source of legacy bugs is that `switch` checks cases using loose equality (`==`), NOT strict equality (`===`).

```php
<?php
switch ($requestMethod) {
    case 'GET':
        $controller->index();
        break; // Crucial: Missing break results in fall-through!
    case 'POST':
        $controller->store();
        break;
    case 'PUT':
    case 'PATCH': // Intentional fall-through grouping multiple cases
        $controller->update();
        break;
    default:
        http_response_code(405);
        echo json_encode(['error' => 'Method Not Allowed']);
        break;
}

$action = 0; // Integer 0

switch ($action) {
    case 'edit': // PHP 7.x evaluates 0 == 'edit' is TRUE! during loose check
        echo "Performing Edit"; 
        break;
    case 0:
        echo "Performing Default Action";
        break;
}
>
```

### `match` Expression (PHP 8.0+)

|      Feature     |                      `switch`                   |                        `match`                        |
|:----------------:|:-----------------------------------------------:|:-----------------------------------------------------:|
| Comparison Type  | Loose (`==`)                                    | Strict (`===`)                                        |
| Return Mechanism | Statement (requires manual variable assignment) | Expression (returns a value directly)                 |
| Fall-through     | Requires explicit `break;` (risks bugs)         | Automatic single-branch execution (no `break` needed) |
| Unhandled Cases  | Silently falls through to `default` or exits    | Throws an `UnhandledMatchError` if no case matches    |

```php
<?php
$statusCode = 404;
// 1. Direct value assignment from return
$message = match ($statusCode) {
    200, 201 => 'Success',
    400 => 'Bad Request',
    401, 403 => 'Unauthorized',
    404 => 'Resource Not Found',
    default => 'Internal Server Error',
};

// 2. Combining match with boolean expressions (Match on true)
$userRole = 'editor';
$isOwner = true;
$permission = match (true) {
    $userRole === 'admin' => 'full_access',
    $userRole === 'editor' && $isOwner => 'edit_access',
    $userRole === 'editor' => 'read_access',
    default => 'no_access',
};
>
```

## Error Handling Mechanics

### The Standard PHP Hierarchy

```
                     interface Throwable
                       /                \
                      /                  \
        class Exception                   class Error
          /         \                     /         \
LogicException    RuntimeException    TypeError   ArithmeticError ...
```

- `Throwable` is the top-level interface for everything that can be thrown via a `throw` statement.
- `Exception` is the base class for application-level exceptions.
    - `LogicException` represents errors in code logic (e.g., `InvalidArgumentException`, `DomainException`).
    - `RuntimeException` represents errors that can only be detected at runtime (e.g., `PDOException`, `OutOfBoundsException`).
- `Error` is the base class for internal PHP engine errors (e.g., `TypeError`, `ParseError`, `DivisionByZeroError`).

### Legacy error handling
Before exceptions became standard, PHP relied on a legacy procedural error mechanism with different error levels (`E_NOTICE`, `E_WARNING`, `E_DEPRECATED`, `E_ERROR`).

#### Custom Error Handlers (`set_error_handler`)
Raw PHP applications often register a global error handler in their entry file (`index.php` or `bootstrap.php`) to intercept traditional PHP warnings/notices and convert them into exceptions or JSON error responses.

```php
<?php
// Converts standard PHP warnings/notices into thrown ErrorExceptions
set_error_handler(function (int $errno, string $errstr, string $errfile, int $errline) {
    // Don't execute handler if error reporting was disabled by the @ operator
    if (!(error_reporting() & $errno)) {
        return false;
    }

    // Convert the legacy error into a modern Exception
    throw new ErrorException($errstr, 0, $errno, $errfile, $errline);
});
>
```

#### The Error Suppression Operator (`@`)
- The `@` symbol placed before an expression instructs PHP to silently suppress any error, warning, or notice generated by that specific line.
- Using `@` forces PHP to dynamically alter `error_reporting` levels before and after evaluating the line, adding runtime overhead in hot loops.
- Developers often use this to quickly hide "Undefined index" warnings. In doing so, they also hide database connection failures, file permission issues, or memory limit warnings, leading to silent failures downstream.
- As of PHP 8.0, `@` no longer hides fatal errors (like `TypeError` or `ParseError`). It only suppresses warnings and notices.

```php
<?php
// Silently opens a file; if it fails, $file is false (no warning output)
$file = @fopen("non_existent_file.txt", "r");

// Silently attempts to parse an undefined array key
$value = @$data['missing_key'];
>
```

#### Graceful Shutdown Handlers (`register_shutdown_function`)
- In raw REST APIs, if a script hits an uncatchable fatal error (like memory exhaustion), execution halts immediately.
- Legacy apps use shutdown functions to output clean JSON instead of raw HTML error logs.

```php
<?php
register_shutdown_function(function() {
    $error = error_get_last();
    if ($error !== null && in_array($error['type'], [E_ERROR, E_PARSE, E_COMPILE_ERROR])) {
        // Clear any output buffer already rendered
        if (ob_get_length()) {
            ob_clean();
        }
        
        http_response_code(500);
        echo json_encode([
            'status' => 'fatal_error',
            'message' => $error['message']
        ]);
    }
});
>
```

### Modern Exception Handling
- Since PHP 7.0, most internal engine errors (like passing invalid types, division by zero, or calling non-existent functions) were converted into `Throwable` objects.
- This allows them to be caught using standard `try-catch` blocks instead of halting execution completely.

```php
<?php
try {
    // Potentially dangerous code (e.g., parsing JSON, executing SQL)
    $data = json_decode($rawPayload, true, 512, JSON_THROW_ON_ERROR);
    $result = $dbWrapper->insert($data);
} catch (JsonException $e) {
    // Triggered ONLY if JSON parsing fails
    http_response_code(400);
    echo json_encode(['error' => 'Malformed JSON: ' . $e->getMessage()]);
} catch (PDOException | QueryException $e) {
    // Multi-catch: Handles both PDO and custom ORM database exceptions
    http_response_code(500);
    echo json_encode(['error' => 'Database operation failed']);
} catch (Throwable $e) {
    // Global fallback catcher for ANY remaining exception or engine error
    http_response_code(500);
    echo json_encode(['error' => 'Unexpected error occurred']);
} finally {
    // ALWAYS executes regardless of whether an exception occurred or was caught
    // Used for cleanup: closing file handles, releasing locks, logging execution time
    $dbWrapper->releaseConnection();
}
>
```
